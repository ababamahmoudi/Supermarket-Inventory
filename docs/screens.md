### Sign-in, setup and lock (E1)

- Keep centered max-420 px company-logo card, Username and Password with show/hide, Sign in and the registered-computer **Recent users on this computer** row. Resolve the persisted directory and company-unique username/alias; the old `supervisor` username signs in to the same Manager identity. Reset/help copy refers to the configured managerial role, not the retired authority role.
- New invited people enter their one-time setup code in Password, then **Choose a new password**. Mandatory setup is the only reachable flow; preserve the existing migrated newemployee forced-change step. Raw code is shown once after Add/reset, never on people rows or recent-user chips. Reload can resume retained setup; consumed codes cannot sign in again.
- Owner/Manager/Branch Supervisor then choose **Passkey** or **Authenticator app code** and complete the clearly **simulated** second sign-in step. No real device enrollment/authenticator secret/SMS/email delivery is implied. Full business screens appear only after required setup/challenge completion.
- Lock shows the current person's name, password field and **Sign in as someone else**. Preserve configured failed-attempt/idle lock and sensitive password re-prompt. Deactivation/changed authority signs out affected shared-browser tabs and rejects their later protected reads/writes.
- After successful explicit **Sign out**, including **Sign in as someone else**, retire the previous person's route and entity/query parameters by returning to the neutral entry route. The next completed sign-in uses the existing permitted role home in the table above. This does not change denial of unauthorized direct links for a signed-in person, mandatory setup restrictions, or the valid current route resumed by unlock and session reload.
- Role labels and fictional names come from seed/config. Demo menu switches the six configured users by resolving their real current permissions; it never bypasses invited/deactivated/custom setup. Reset confirmation states that the six demo people are restored as well as fictional business state.
- Location pill contains only permitted concrete locations, **All my locations** for multiple assignments and **All locations** for Owner/Manager. Fresh sign-in defaults to an allowed registered location, otherwise sole assignment, otherwise the appropriate aggregate. rh-supervisor on the North York demo computer starts at **All my locations** for Richmond Hill/Newmarket. - Tabs: **Drafts · Processing · Needs review · Ready to post · Posted · Cancelled**. Search by supplier, number, date.
- **New invoice** presents **Upload** and **Manual entry** as adjacent clear choices. Upload retains the existing reading/review flow. Manual entry opens the same header and lines without waiting for AI: the Owner/Manager chooses branch, supplier (with **+ Add supplier**), supplier invoice number, invoice date and payment terms, then adds products (with **+ Add new product**), quantity and unit cost. The existing subtotal/tax/final-total, receiving employee/date and other mandatory fields remain in the review form.
- **+ Add supplier** opens the same max-720 px form as Suppliers. Invoice-created suppliers are Proposed for every creating role until explicit Owner/Manager review/confirmation; only standalone Owner/Manager additions are immediately Confirmed. Branch Supervisor and Floor Worker have no opening-balance fields. Owner/Manager confirmation is required before posting the worker's invoice. Deactivated suppliers are absent from new-invoice choices; their old invoice links remain readable.
- **+ Add new product** opens the shared product editor in new mode. Owner/Manager additions are Active immediately; Floor Worker additions remain Pending approval with no opening-count controls. Selecting a newly saved supplier or product returns to and updates the same invoice without losing existing header/line edits.
- Manual drafts can be saved without an original. The original photo/PDF dropzone stays available, and posting remains blocked until the original is attached and every existing posting/line-review requirement is met.
- **Lines table (review):** compact rows with shared column headers: description, matched product, qty, unit/units per case, unit cost, line total, calculated selling price, current price, status badges. Matched/confirmed lines stay collapsed; lines needing decisions open automatically; each line can be opened on click. An unassigned code reads **No Product Code yet** in muted text.
- Each line has segmented **Track date: Yes / No**, initialized from an explicit product Yes/No preference; unset asks and blocks posting. Yes reveals required Expiry/Best before/date and optional lot. Confirm each line normally. Preserve categories' prompting/default rules and stored four-decimal costs. **Mark as short** and lower-price questions remain available. A pending calculated price uses a **Pending** pill with **Goes to approval when posted** below; it is not an existing approval before posting.
- The document pane is sticky beneath the sticky top bar on wide screens. The invoice-amount note sits directly below the four summary tiles. **Use fictional demo answer** is available only in the top-bar Demo menu.
- Banner for blockers (supplier not confirmed, original file missing) above the bottom bar. Bottom bar spans the review width with `--surface` fill: **Save as draft** and **Post invoice**. Reserve content space so it never obscures fields.
- **Posted detail:** clean readable document header, lines (product, cases/units or kg/lb, retained unit cost/line total/tracked date), recorded short/extra/short-dated decisions, totals and actual original, with History/linked returns/credits. No disabled gray form or draft auto-save message. Owner/Manager **Correct invoice** opens populated lines/reason and impact preview (payable, Received, approvals, dates), then confirmation; append original-linked version and show **Corrected** with both versions in History. Original images fit/zoom; PDFs show viewer/page navigation/Download. Missing manual file shows **No original attached / Attach original**; posting still needs the original.

### Products

One-line toolbar: search pill, compact filters (pricing category, AI category, status, supplier, has pending price, has offer, **Manual prices**), **Clear filters**, result count and Columns. Click product name/row to open its page and Back link; no duplicate View or detail panel below the list. Owner/Manager Edit remains; **⋯ → Add date** opens the quick-add page preselected. Weight Unit size reads **Sold by weight**, with approved price first and converted price smaller below without a leading dot.

Product page: current-language name primary, other-language name directly below and muted; readable details using available page width, with related values grouped. Show names EN/FA, description, unit size, Product Code (read-only), category, tax profile, barcodes, approved/pending/branch prices, supplier products (SKU, pack size, last cost, role restrictions), offer, **Last received** per location and recorded changes. No stock estimate. Owner/Manager sees **Store cost**, **Margin %** in the list and cost history on the product page; staff prices retain the **Manual price** pill and rule/manual pair, with margin hidden from Worker/Cashier. New products created from invoices appear as **Pending approval**.

**Edit** appears on every product row and the product page for the Owner/Manager only. The same dialog opens from Lookup. Fields: names EN/FA, description, unit size, **Sold by: Each / Weight**, category, pricing category, barcode, supplier, date tracking, selling price labeled per unit/per lb (or configured kg display). Choosing Date tracking Yes immediately reveals the same-form Date tracking group: Remind me [30] days before expiry and this location's date rows, type/date/quantity/lot add/change/remove. Save commits product and dates together; Cancel commits neither. Required English name/pricing category; Persian name/descriptions/category optional with English fallback. A price change asks for **All branches** (default) / **This branch only**, records the Owner/Manager decision, retains invoice-calculated price and invoice number, and appends a reversible before/after History entry. Example provenance, only when these values exist: **Calculated from invoice FV-20417: $2.99 · Changed by [name] on [date]: $3.29**. Worker receiving proposals are unaffected; Floor Workers and Cashiers do not see Edit.

**Add product (B, item 45)** is a Owner/Manager-only action at the top right of Products. It uses the same editor in new mode: names EN/FA, unit size, category, pricing category, barcode, supplier, date tracking, last unit cost before tax, selling price. No Opening count field in Phase 1. Product Code is assigned by the app and is never reused. Pricing fills the selling price; a changed value records a manual override and a below-minimum-margin value needs confirmation. Warn about a similar product name with a link and block a conflicting barcode. Save creates an Active product and History entry; no stock-count transaction is available; historical movements remain retained. Floor Workers and Cashiers have no standalone Add product; a worker's invoice-only **+ Add new product** remains a proposal.
